# EAI-CAM-r1-plan-v1 (route standard + opus reviewer on K1 for the native interop; NOT yet approved)

User request 2026-10-11: Settings gets Source "Camera MVS"; Settings gets Connect Camera; a new tab "Live camera" with a Set parameter panel on the right when the camera source is on; images in the other tabs can be captured directly from the camera (modify the current image or add a new image).

User decisions: parameter set = Exposure, Gain, Gamma, Trigger mode, Pixel format, Frame rate, ROI (Width/Height/Offset), White balance (hide what the camera does not support, Auto button for Exposure/Gain when supported); Modify = overwrite the current image directly, NO backup (user's choice; labels kept, every cache/hash of that image invalidated); captured images saved as BMP; no real camera on this PC now: build against a fake camera, real-camera behaviour stays unverified.

Discovery facts (haiku explorer, unverified): EasyLabel/src/EasyLabel.Camera has only interfaces (ICameraProvider.EnumerateAsync/Create, ICameraSource Open/GrabOne/Stream/Close, CameraInfo, CameraState, CameraPixelFormat, CameraFrame with ArrayPool) and the MVS loader (MvsSdk/MvsNative: only MV_CC_GetSDKVersion declared, runtime at C:\Program Files (x86)\Common Files\MVS\Runtime\Win64_x64\MvCameraControl.dll); no parameter API; no camera UI or settings; tabs = WorkflowStep {Inspect, Label, Train} switched by MainViewModel.TabSteps/StepTabIndex and DataTriggers in MainWindow.xaml; Settings pages = SettingsCatalog + SettingPageModel (AgentsSettingsView is the example); SegAiSession.AddImage only copies, no overwrite API.
