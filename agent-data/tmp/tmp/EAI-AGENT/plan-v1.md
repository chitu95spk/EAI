# EAI-AGENT-r1-plan-v1 (architect pass, Opus, read-only; NOT yet approved by the user)

Invariants: EasyLabel files only (+ tmp/EAI-AGENT, artifacts/EAI-AGENT); nothing the agent proposes reaches a document without Accept; each Accept = one undo unit; stale targets skipped and reported; rectangle/polygon/oriented_rectangle proposals and proposals.json stay byte-compatible (new fields optional); AgentCache.Key signature unchanged (new inputs join SkillPackHash list); no third-party MCP server starts unless its exact name/command/args/version are approved, the app never downloads or installs one; agent file access limited to the run folder; logs hold prompt length and cost only; runs stay stateless (--no-session-persistence), chat history is for the user; WPF-UI controls only (rule 0.2a), no tips text, every string in Strings.resx + Strings.vi.resx + Strings.Designer.cs.

## Architecture
A1 Popup = owned non-modal FluentWindow Views/AgentChatWindow (Owner=MainWindow, ShowInTaskbar=false, position/size saved in AppSettings and clamped to the work area, DataContext = LabelStepViewModel, hides on step change/project close). Not AvalonDock (layout XML, multi-DPI floating risk), not Popup (closes on click-away, no resize).
A2 Round 44 px ui:Button (AutomationId AgentChatButton) in a pinned bottom row: ToolStripView root becomes Grid (tool ScrollViewer on top, button row at bottom); command bound in MainWindow.xaml:838 to LabelStep.OpenAgentChatCommand; opening selects the Agent source.
A3 Layout: chat list on top; prompt box (multi-line, Enter runs, Shift+Enter newline); row with Effort (3 segmented radios, BarCaptionStyle), Mode (ui:DropDownButton with ui:MenuItem), Run, Check, Cancel, Options (Language, Precision, Model, shape list, label strip moved from LabelStepView). Old prompt bar LabelStepView.xaml:161-191, 242-363 removed; Accept/Reject and count stay on the main bar.
A4 Chat history: <project>\.easyai\agent-chat.jsonl (time, role, mode, effort, prompt, image(s), boxes proposed/accepted/rejected, cost, turns, outcome); cap 500, window shows last 100; click reuses prompt.
A5 Memory: <project>\.easyai\agent-outcomes.jsonl, one record per resolved agent suggestion (time, rel, run id, label, shape type, action, accepted/rejected, normalised w/h), cap 2000 records / 512 KB. Deterministic digest (no model call), <= 1200 chars: per-label accept rate rounded to 10%, p10-p90 size of accepted shapes in 5% buckets, most rejected patterns. Computed once per run/batch and frozen so the cache key only changes when the digest text changes. memory_add notes unchanged (6000 chars).
A6 Batch (All | Current | Remaining): sequential AgentBatchRunner reusing AgentRunner, _aiSuggestions and the cache. Current = open image; All = every image from the current one; Remaining = images with no shapes and no pending suggestions. Open image uses Canvas.Document, others LabelMeIO. Before each image: cost cap (default 2.00 USD) and image cap (default 50); cached result costs 0; if the agent reports no cost only the image cap applies. Progress, cumulative cost and Cancel (CancelAndKill) reuse the progress row. ApplyAgentResult split into store-for-rel and show-if-open. Remaining runs in two phases: current image first, chat shows 'Waiting for review' + Continue; after Accept an experience block (<= 1500 chars, text only: label, type, relative bbox size, rounded points for up to 8 shapes, no image) goes into the system prompt.
A7 Check: list_shapes returns id (index) and fp (shape hash); propose_shapes accepts optional target, action (add|replace|remove), note required when target; remove needs no points; one action per target. SegAiSuggestion gets optional Action, TargetIndex, TargetHash (positional record, optional parameters at the end). Canvas: replace = new outline dashed + target highlighted; remove = target dashed red with cross. Accept splits by action, re-checks target hash, applies via new DocumentEditor.ApplyReview(adds, replacements, deletions) (built on Change) as one undo unit. Check prompt composed by the app + check.md skill. Check works on the current image only in r1.
A8 Skills: new detect.md, judge.md, check.md, repeat.md; update read-image.md. New app-owned MCP tools: grid_crop (crop with labelled coordinate grid), render_overlay (existing shapes + proposals with ids on a crop), measure (sizes, IoU, overlaps, duplicates); added to the Claude allow-list and Codex enabled_tools. Enable toggle fix: Settings shows the EasyAI run skills (built-in + user folder %LOCALAPPDATA%\EasyAI\skills); disabled names kept in AppSettings and filtered in ReadSkillTexts; the app does not rely on claude -p loading ~/.claude/skills.
A9 External MCP registry: %LOCALAPPDATA%\EasyAI\mcp-servers.json (name, source URL, version, command, args with {run}, working folder = run folder, access summary, explicit tool list, approved hash SHA-256 of name+command+args+version). Approval dialog shows all of it; any edit un-approves. --strict-mcp-config stays; mcp.json gets approved servers; --allowedTools lists their tools one by one (no wildcards); Codex gets -c mcp_servers.<name>.* with enabled_tools. Approved-set hash joins the cache key. No server ships enabled; the user installs servers outside the app.

## Risks
Shape indexes shift between Check and Accept (hash check, stale skipped + reported); digest change invalidates cache (rounding + freeze per batch); batch cost runaway (cost cap, image cap, Cancel); Codex may not report cost (image cap only); third-party server may access more than it claims (dialog says so, no auto-install); ui:DropDownButton under rule 0.2a (fallback: segmented radios).
Unverified: all builds/tests/smoke; token savings in real runs; whether claude -p loads ~/.claude/skills; Codex cost reporting.
