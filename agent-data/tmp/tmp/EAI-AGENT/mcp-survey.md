## Searched and NOT found (unverified absence)
- MCP for grid overlay or zoom-to-region as a dedicated tool (only partial: replicant-mcp grid is screenshot-oriented; mcp_images/imagesorcery cover crop/resize/draw).
- MCP for IoU or box-verification (no hit; build it).
- MCP for SAM with point/box/mask prompts (only a whole-image SAM wrapper in a CVDLT server listing, n/v).
- Self-hosted Grounding DINO MCP (only the cloud DINO-X one found).
- CVAT MCP server (none found; not verified that none exists on GitHub topics).
- Persistent memory beyond the reference server: community forks (StevenWangler/mcp-memory-server, MemoryMesh) not checked in README.

## Recommendation
1. Do not install third-party MCP servers into the production auto-label path; they run with user-level filesystem/network access and several are immature (0-1 stars) or archived.
2. Implement the image tools (crop, zoom, grid overlay, measure) and IoU/overlay checks inside the app as app-owned MCP tools (Pillow/ImageSharp, plus a bbox-visualizer-style renderer); the app already holds the images and must verify box coordinates itself.
3. For detection/segmentation, expose the app's own native YOLO/SAM2 path as an MCP tool rather than a third-party YOLO server; DINO-X only if uploading images to a cloud service is acceptable.
4. If a third-party image helper is wanted for evaluation only, imagesorcery-mcp (MIT, 333 stars) is the most complete, but pin the version, run stdio, and review its post-install model downloads first.
5. Scope the agent with a filesystem server or equivalent path sandbox limited to the run folder (tmp/ or artifacts/), and skip CVAT/Label Studio/Roboflow MCPs unless EasyLabel adds an export to those tools.
