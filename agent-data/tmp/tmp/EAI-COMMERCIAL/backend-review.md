## Online mode feasibility (third run mode: realtime defect detection + position, < 50 ms per 5 MP image, 1 Gbps)
Evidence status: no measured SegAI/ONNX inference latency for a 5 MP frame exists in artifacts/, tmp/ or CODEX_HISTORY.md (searched). Everything below marked EST is arithmetic from stated assumptions, not a measurement.

### Measured numbers that do exist
- Custom YOLO (detect ONNX, DirectML): "5 suggestion(s) in 113 ms" (tmp/EAI-PLUS/deferred.md:145, artifacts/EAI-PLUS/smoke/r16). Machine/GPU and input size not stated; already over 50 ms.
- Segment AI V2 training (not inference): 84 images 2448x2048, 640 input, 20 epochs, 16 logical CPUs: native features 12.95 s (~154 ms/image feature extraction at 640 input on 16 threads), head 60 s (tmp/EAI-PLUS/deferred.md L49). Feature extraction = the same frozen MobileNetV2 ONNX via OpenVINO that inference uses, so ~150 ms/image on 16 cores is an upper-bound hint, and the 2-core target has 1/4-1/8 of that CPU.
- Production 2-core i7-7600U: Learning(Yolo)+Pattern tools: 200 ms single tool, 500-1128 ms concurrent (memory runtime-target-2core-word.md). In Word mode concurrency is forced to min(tools, cores).
- Memory notes: ECAT dropouts occur when camera CPU load starves the cyclic thread (e804, ecat-send-stall); an Online mode on the same PC competes with motion.

### What can meet 50 ms and what cannot
- CAN (architecturally): SegAiInferer (SegAI/Engine/SegAiInferer.cs:52, Predict at :296-316) calls native SEGAI_InferPredict (BeeNativeSegAI), the same engine EasyVision ToolSegmentAI loads from .segai; it takes a raw BGR pointer + ROI, so no managed copy is needed. It is a frozen-backbone + small MLP head design (cheap postprocess). A user ROI and the model input size (640 default) shrink the cost.
- CANNOT: any per-frame LLM/agent call (seconds, USD per frame, `claude -p` process spawn alone is hundreds of ms); SAM2 (encoder is heavy, CPU graph optimisation must be off, DML unmeasured); YOLO-seg/obb results are not usable in EasyVision and need CUDA to train; RT-DETR (experimental, 6 GB VRAM). The Agent should only configure Online mode (pick model, ROI, threshold, class rules) and never sit in the frame path.

### Where time goes for one 5 MP frame (EST, 2448x2048 BGR = 15.0 MB)
| Stage | EST on 2-core i7-7600U | Note |
|---|---|---|
| Camera/transport 1 Gbps | ~120 ms for raw 15 MB (1 Gbps ~ 125 MB/s usable ~ 110); ~30-40 ms mono 8-bit 5 MB (~40 ms); JPEG ~0.5-1 MB ~ 8 ms | Raw BGR cannot meet 50 ms over 1 Gbps; send mono or compressed, or run inference next to the camera. |
| Decode (JPEG 5 MP, OpenCV) | 25-50 ms single thread (EST) | Skip when frame is raw mono; SIMD libjpeg-turbo or GPU nvJPEG on the server. |
| Resize/ROI to 640 | 3-8 ms | Use INTER_AREA/LINEAR on the ROI only. |
| Backbone MobileNetV2 @640 (OpenVINO CPU) | 80-200 ms (EST, from ~154 ms on 16 threads and a 2-core part) | Dominant. OpenVINO INT8 (roadmap H3) might give 2-3x. |
| Head + postprocess (V2 MLP 448->32->3, connected components, position/box) | 5-20 ms | Cheap relative to the backbone. |
Conclusion (EST, to be confirmed by a measurement): on the 2-core target the sum is roughly 150-300 ms per 5 MP frame, i.e. 3-6x over budget. CPU-only 2-core can reach < 50 ms only for a much smaller effective input (small ROI / ~320 px / tile-skipping), INT8 backbone, and mono pre-reduced frames, and then with no headroom for camera + EtherCAT on the same PC.

### Recommendation
- Realistic: Online = a separate inference process on a stronger LAN node (any GPU or an 8+ core CPU) fed over 1 Gbps with mono/JPEG frames; or on-camera-PC only at reduced ROI/size after the user passes a built-in latency probe. A 1 Gbps link is enough only for compressed or 8-bit mono frames (see table), not raw BGR.
- Gate by measurement: Online mode must refuse to start (or label itself "best effort") when the warm-up probe p95 exceeds the budget.

### Backend work items (concrete)
1. Measure first (S): script that runs SegAiInferer.Predict on a 2448x2048 frame at inputs 640/448/320 on CPU(OpenVINO)/GPU on the target and one LAN PC; report p50/p95 per stage. Everything above is EST until this exists.
2. Inference service (M/L): headless EasyLabel.Infer host (new project) wrapping SegAiInferer; model loaded once (warm), one inference thread per device, ROI + threshold per request; no UI, no agent, no SAM2.
3. Frame protocol (M): length-prefixed binary over TCP (or gRPC) on a persistent connection: header (frame id, ts, w, h, pixel format mono8/BGR/JPEG, ROI, model id/version, crc), payload; reply = frame id, status, defects[class,score,area,centroid,box,angle], timings per stage. Version field + model-hash check so client and server cannot disagree on model.
4. Back-pressure (M): bounded queue of 1-2 frames; drop-oldest ("latest wins") and a dropped counter; never let the camera thread block; per-request deadline (50 ms) with a timeout result "late" rather than a stale answer.
5. Batching (S/M): none for latency mode (batch=1); optional micro-batch only on GPU server for multi-camera, capped by the deadline.
6. Warm model + failover (S): load and run 3 dummy frames at start; keep OnnxSession/native handle resident (the factory already supports one resident); automatic restart and a fallback to "reject-all/hold" signal on service failure.
7. Process isolation and priority (S): service at AboveNormal on the LAN node; on the camera PC pin away from the ECAT core (reuse BeeGlobal CpuAffinityService rules) to avoid E-804 starvation.
8. Health/latency telemetry (S): rolling p50/p95/p99 per stage, queue depth, drops, model hash, GPU/CPU use, exposed as a status request and a rotating log (ties to BE-13); alarm when p95 > budget.
9. Licensing/gating (S): Online behind the licence seam (BE-14) and the hardware probe (roadmap T3).
10. Agent role (S): Agent writes a config JSON (model, ROI, threshold, class rules) and runs a dry-run on saved images; the config is then frozen and signed with the model hash; no LLM in the frame loop, cost cap irrelevant.
