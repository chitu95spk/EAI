# EAI-ONL3: SegAI V2 mask Predict non-backbone latency

Read-only source/artifact investigation, 2026-10-17. No source edits, build, test, benchmark, model changes, or Git commands. The only created file is this report. Task reference: EAI-ONL3; no tracking/map changes.

## Finding

The supplied approximately 50 ms measurement includes **two network executions**, not one backbone followed by one measured head. `Classify` executes the production full graph, upsamples its outputs, and then executes a separate backbone-only graph for diagnostics (`BeeNativeSegAI/SegV2Core.cpp:283-318`). That second request costs **15.36 / 15.02 ms p50** for ROI512 / ROI960, and **16.83 / 16.82 ms** under the `threadsall` colour/JPEG configurations. It is inside `v2_total`, `inferer_total`, `export_total`, and managed `infer`, but outside `v2_infer`, `v2_tensor`, and `v2_upsample`.

`head_ms = max(0, full_graph_ms - separate_backbone_ms)` (`BeeNativeSegAI/SegAINativeExport.cpp:754-761`). The graphs are separately compiled and run, and subtraction is clamped. A zero head row therefore does **not** establish that actual head execution is free. In the primary ROI512 data, the full graph is 14.37 ms p50 and the standalone backbone is 15.36 ms p50.

After this diagnostic overhead, the largest costs are full-frame result materialization/copying, CPU preparation/tensor fill, and two-stage probability upsampling. Managed ROI/component analysis is another measured **19–22 ms**, but belongs to the separate `postprocess_positions` stage, not to the approximately 50 ms `infer` stage.

## Full execution trace and data sizes

1. `SegAiPredictor.Predict` → `PredictCore` (`EasyLabel/src/EasyLabel.SegAI/Inspection/SegAiPredictor.cs:165`, `:182-207`) validates input/ROI, obtains BGR via `AcquireInferenceInput` (`:369-390`), configures the inferer and calls mask `Predict`. Continuous V2 BGR uses a refcounted Mat header; it does not copy the full 15,116,544-byte input. No duplicate managed normalization is present. Benchmark host preparation is separate from `infer`.
2. `SegAiInferer.Predict(Mat,Rect,float)` passes `Data`, dimensions and stride to its pointer overload (`Engine/SegAiInferer.cs:328-350`). `Interop/SegAiInfererNative.cs:44-61` declares the Cdecl native mask API, `:64-88` declares buffer getters/free and timing export. The full interop path is under `EasyLabel/src/EasyLabel.SegAI/`.
3. `SEGAI_InferPredict` wraps the existing BGR pointer without pixel copying (`BeeNativeSegAI/SegAINativeExport.cpp:47-52`, `:640-644`). `SegInferer::Predict` selects a clipped ROI header `bgr(r)` and calls V2 (`BeeNativeSegAI/SegInferCore.cpp:211-224`). ROI512 has **262,144** pixels; ROI960 has **921,600**, versus **5,038,848** in the full input. Optional original-input speed-scale handling exists at `:217-223`; changing it is not proposed.
4. `SegV2Model::Predict` resets timers and enters compact single-scale inference (`BeeNativeSegAI/SegV2Core.cpp:2547-2558`). `PredictCompact` selects device, computes compact output size, and prepares the network canvas (`:558-592`). `PredictFrame` reuses compiled/request state by device and canvas size (`:773-783`) then calls `Classify`. Original-input GPU tiling is conditional at `:795-798`, not a consequence of merely passing the 2592x1944 outer frame: V2 sees the ROI.
5. Fixed-Side `Prepare` scales the ROI to fit Side and fills a letterboxed canvas (`:247-268`); `Input` allocates f32 NCHW, splits BGR into three u8 planes, then converts reversed planes into RGB with the existing mean/sd affine factors (`:270-281`). For a **960x960 canvas**, tensor payload is **11,059,200 bytes**, split buffers total **2,764,800 bytes**, and the canvas another **2,764,800 bytes**. Square ROI512 still expands to that canvas on the fixed-Side path; ROI960 can hit an exact-size fast path. Changing Side is not proposed. These canvas counts are conditional on fixed-Side mode; the summary does not export every model flag.
6. Production `request.infer()` is timed with `set_input_tensor` in `v2_infer` (`:287-311`); transfer/synchronization internal to OpenVINO is not separated. `get_output_tensor`/`data<float>()` and two bilinear resizes per class are under `v2_upsample`. For legacy three-class fixed-Side 960 mode, grid is 120x120; three 960x960 f32 `big` destinations write **11,059,200 bytes**, followed by three 240x240 f32 compact maps writing **691,200 bytes**. Removing an intermediate interpolation is not assumed to preserve values.
7. The extra backbone executes **here**, after upsampling (`:313-316`). `PredictCompact` records `timeClassified` only after it returns (`:592-593`), so the added pass is in `v2_total` and absent from all eight exclusive V2 phases. This explains the otherwise approximately 15 ms hole in their sum.
8. Compact NG/OK foreground comparisons, morphology, 8-connected labels, component means and minimum area filtering happen at `:594-672`, measured together as `v2_ccscore`. Two nearest resizes restore byte score maps to ROI dimensions (`:673-681`). Generic class tables branch at `:560` to `PredictCompactClasses` (`:345-420`), with analogous timing boundaries; no class/accuracy change is proposed.
9. `SegInferer` thresholds NG at ROI resolution, counts accepted pixels for score, but for partial ROI creates **three full-frame 5,038,848-byte maps**: NG confidence, normal confidence, binary mask (`SegInferCore.cpp:230-240`). That is **15,116,544 zero-filled bytes**, plus ROI pastes totaling **786,432 / 2,764,800 bytes**. Hence output tail barely shrinks between ROI512 and ROI960. The helper `FilterConnectedComponents` at `SegInferCore.cpp:135` is **not called by this V2 branch**; compact native filtering is already described above.
10. Export copies the full mask to new[] (`SegAINativeExport.cpp:650-659`); managed Predict allocates and copies a full byte[] (`Engine/SegAiInferer.cs:368-371`). It then fetches NG and normal confidence through exports that each allocate/copy another full map (`SegAINativeExport.cpp:771-795`), followed by managed array allocation/Marshal.Copy/free (`Engine/SegAiInferer.cs:565-631`). With normal present, the three maps undergo **six full-map memcpy/Marshal.Copy operations: 30,233,088 payload bytes copied**, approximately **60.5 MB read+write traffic**, before native zero fills, managed zero initialization, ROI pastes, or later analysis. Managed arrays alone allocate **15,116,544 payload bytes per Predict**, independent of ROI size. No source evidence makes the BGR input interop copy a bottleneck.

## Recommended priority and limits

1. Disable split diagnostics and rerun the same configuration only when runtime execution is separately authorized. Existing code already supports this; it should remove one measured 15–17 ms request without changing inference outputs.
2. Consolidate output ownership/copy-out and retain ROI-local work until the final required full-frame representation. This targets measured output plumbing of 11.20–12.63 ms mean and separately the 19–22 ms managed postprocess envelope. Savings will be smaller than the entire envelope because required output arrays/metrics still need work.
3. Reuse Prepare/Input/upsample buffers and add exact square/no-resize fast paths. Preparation + tensor + probability upsampling currently total **8.340855 / 7.208875 ms mean**. Preserve operation ordering and numerical results; interpolation collapse, lower Side, fewer scales/classes, changed thresholds/morphology, reduced precision, or skipped normal analysis are not recommended here.
